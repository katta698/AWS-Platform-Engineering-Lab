# Week Folder Template

Copy this structure for every new week. The split is simple:
- **Deploy** = everything Terraform/scripts need at runtime → stays at root level
- **Reference** = docs, blog, diagrams → lives under `docs/`

---

## Standard Layout

```
week-XX-short-name/
│
├── README.md                          ← single entry point (GitHub renders this)
│
│── terraform/                         ── DEPLOY ──────────────────────────────
│   ├── environments/
│   │   └── dev/
│   │       ├── main.tf                ← calls all modules
│   │       ├── variables.tf
│   │       ├── outputs.tf
│   │       ├── terraform.tfvars       ← gitignored (copy from .example + fill secrets)
│   │       └── terraform.tfvars.example
│   └── modules/
│       └── <module-name>/
│           ├── main.tf
│           ├── variables.tf
│           └── outputs.tf
│
├── lambda/                            ── DEPLOY ──────────────────────────────
│   └── <function_name>/
│       └── handler.py                 ← source only; Terraform packages the zip
│
├── scripts/                           ── DEPLOY ──────────────────────────────
│   ├── deploy.sh
│   └── cleanup.sh
│
├── step_functions/                    ── DEPLOY (if used) ────────────────────
│   └── state_machine.json
│
├── glue/                              ── DEPLOY (if used) ────────────────────
│   └── scripts/
│       └── job_script.py
│
└── docs/                              ── REFERENCE ───────────────────────────
    ├── explainer.md                   ← real-world explanation
    ├── execution-guide.md             ← step-by-step deploy walkthrough
    ├── commands.md                    ← useful CLI commands
    ├── interview-questions.md
    ├── resume-bullets.md
    ├── references.md
    └── blog/
        ├── blog.md
        ├── week-XX-blog.html          ← Blogger-ready HTML
        ├── linkedin-post.txt
        └── screenshots/               ← kept local, gitignored
```

## Hard Rules

| Folder | Can it move? | Why |
|--------|-------------|-----|
| `terraform/` | ❌ No | Obvious |
| `lambda/` | ❌ No | `${path.module}/../../../lambda/` hardcoded in Terraform lambda module |
| `step_functions/` | ❌ No | `${path.module}/../../../step_functions/` hardcoded in step_functions module |
| `glue/` | ❌ No | Uploaded to S3 by deploy script using relative path |
| `scripts/` | ❌ No | Uses `PROJECT_ROOT=$(dirname "$SCRIPT_DIR")` to locate `terraform/` |
| `docs/` | ✅ Yes | Pure reference, no runtime dependency |

**Never put these at the week root:**
- Blog posts, explainers, LinkedIn content → `docs/blog/`
- Command cheatsheets, screenshots guides → `docs/`
- `.html` files, `.txt` content files → `docs/blog/`

## Gitignored by Default (lab-level .gitignore)

These are already covered — you don't need to add them per-week:

- `terraform.tfvars` — secrets; always copy from `.example`
- `tfplan` — binary build artifact
- `lambda/builds/` and `*.zip` — generated by Terraform
- `docs/blog/screenshots/` — large image files, keep local only
- `.terraform/` and `*.tfstate*` — Terraform internals

## deploy.sh Pattern

Keep consistent across weeks so GitHub Actions can call any week uniformly:

```bash
#!/usr/bin/env bash
set -euo pipefail
ENVIRONMENT="${1:-dev}"
REGION="${2:-us-east-1}"
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"            # ← resolves to week-XX/
TF_DIR="$PROJECT_ROOT/terraform/environments/$ENVIRONMENT"

cd "$TF_DIR"
terraform init -reconfigure
terraform plan -var-file="terraform.tfvars" -out=tfplan
terraform apply tfplan
```

## Lambda Module Pattern

Use `archive_file` so Terraform builds the zip automatically — no committed zips:

```hcl
data "archive_file" "my_function" {
  type        = "zip"
  source_file = "${path.module}/../../../lambda/my_function/handler.py"
  output_path = "${path.module}/builds/my_function.zip"
}
```

`path.module` = `terraform/modules/<module>/`, so `../../../` = week root. `lambda/` is always at the week root.

## GitHub Actions

The lab-level workflow (`.github/workflows/terraform-deploy.yml`) handles all weeks automatically:
- **PR** → runs `terraform plan`, posts output as PR comment
- **Merge to main** → runs `terraform apply` (requires `production` environment approval)
- **Manual** → `workflow_dispatch` lets you pick week + environment + action (plan/apply/destroy)

No per-week workflow files needed.
